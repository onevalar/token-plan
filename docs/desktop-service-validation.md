# Windows / Ubuntu 验证状态

桌面客户端使用原生窗口、Avalonia 控件和系统托盘，与 Mac 共用品牌、五种语言和价格数据。Windows 和支持托盘的 Linux 使用紧凑弹出面板，设置在面板内完成；无托盘的 Linux 保留系统窗口入口。代码检查、模拟验证与真实账户验收是不同阶段；本轮按用户要求进行模拟验证，真实账户由用户安装后检查。

## 已实现的日常操作

- 首页进入详情，详情的用量始终展开；用量和设置共用刷新入口，标题旁不重复显示连接状态。
- 首页只有刷新与选项两个操作；选项集中订阅服务、通用设置、关于和退出。服务管理通过返回回到首页，不再保留顶部导航、概览大标题或服务数量计数。
- 服务管理负责启用、禁用、排序；API Key 只在对应服务详情编辑，并提供官方获取入口。刷新保留未提交的输入。
- 备注的折叠按钮在右侧，展开状态与草稿在刷新中保留。
- 显示内容采用“内容项 / 显示配置 / 托盘”表格；状态为首页、仅详情、隐藏，至少保留一项首页内容。支持调整顺序和恢复显示默认值；备注位于其后。托盘每个服务最多选择两项，选满后禁用其他选项，计数保持中性；用简短说明解释显示位置和更换方式，不显示常驻警告。
- 浅色、深色、跟随系统、已用/剩余、紧凑布局、隐藏数值；隐私模式同时遮挡金额、进度条和托盘数值。
- 通用设置合并显示与外观，集中语言、主题、用量显示、系统托盘、刷新间隔和登录启动；通知、隐私与高级设置从该页进入并返回。通知与 Mac 一样分为即将耗尽、接近上限、将会耗尽，首次读取不提醒，投递失败允许重试。外观选项按用量显示、应用界面、系统托盘分组，支持减少动画。
- 订阅服务先显示用量总览，再显示服务管理；原用量历史包含今日、昨日、30 天的 token/费用汇总和每日明细，可切换费用、每百万 token 费用和 token 总量。费用按模型估算，不等于订阅账单；无法计价时显示不完整，不冒充零费用。
- 主用量成功后，附加套餐/重置卡接口单独限时；附加请求超时或限流不会抹掉主用量。用户取消仍会停止整个刷新。
- 多配置目录账号、Codex Swap 和 Claude Swap 文件凭据的只读读取；账号自身 CLI 登录文件不因切换显示而被替换。Claude 还会扫描用户目录下带有有效账号信息的 `.claude-*` 独立目录，同一账号去重，独立目录凭据缺失时不会回退到默认账号。默认及附加账号均显示邮箱和订阅等级。

- 关于显示应用介绍、实际构建版本、运行平台、许可证与隐私说明，提供项目主页、问题反馈、隐私政策和开源许可入口。

API 密钥不进入偏好或历史。Windows 使用当前用户 DPAPI；Ubuntu 使用仅当前用户可访问的文件。Grok 续期与 Mac 一样需要保存新的 CLI 令牌，写入时保留其他账号与未知字段，并在检测到文件变化时拒绝覆盖。

新增 BouncyCastle.Cryptography 用于跨平台 Ed25519 签名；.NET 内置 API 不提供与此格式匹配的统一实现。版本与依赖锁定，许可证随安装包携带。Avalonia.Headless 仅用于界面测试，不进入产品依赖。

## 平台适配与验收边界

- macOS 专属的 iCloud 和透明度设置不进入 Windows / Ubuntu 的设置菜单，也不列为跨平台待补功能。Windows / Ubuntu 使用系统托盘与原生窗口控件。
- Antigravity 在 Linux 上先尝试当前用户的本地语言服务额度接口，再尝试系统凭据和 Cloud Code；缺少凭据读取工具和钥匙串读取失败分别报告。旧式逐模型 RPC 尚未移植。
- 多账号支持附加账号的独立显示设置、备注、隐藏和额度历史清除；不包含 Mac 的全部 pi/钥匙串来源。设备 token 历史不归属到附加账号。
- 价格使用内置快照并在线更新三个公开来源，后台更新失败保留已有价格并记入日志，不在首页显示提示；支持 Codex 回退模型设置，变更后重算本地历史。
- 系统通知实际投递、开机启动、托盘恢复、不同 DPI、安装升级卸载和真实付费账户，仍需在 Windows/Ubuntu 真机验收。系统策略可能阻止通知或隐藏托盘。
- Windows 安装包未签名。Ubuntu 包面向 x64，安装依赖包含 libsecret-tools 和 libnotify-bin。

因此不能把本轮模拟检查通过表述为“所有功能与 Mac 完全一致”或“所有真实服务均已验证”。

## 界面验收范围

浅色与深色均检查首页、服务管理、详情用量/设置、合并后的通用设置、通知、隐私与高级设置、订阅服务内的用量总览和关于。自动化覆盖返回来源、嵌套返回、凭据入口、最后一项首页内容保护、托盘两项上限、详情完整展开及隐私遮挡。新增 Windows/GNOME 的 Ctrl+Alt+U 快捷键、附加账号独立设置和 Codex 回退模型选择。其他 Linux 桌面可自行绑定 tokenplan --toggle；任意快捷键录制、自动应用更新及全部凭据来源仍未对齐。原生托盘与快捷键仍须安装包实测。

### 多账号支持范围

- Claude：Windows/Linux 支持独立 `.claude-*` 目录、`CLAUDE_CONFIG_DIR` 和 Claude Swap 文件凭据；按账号身份区分额度及附加账号的本地额度历史。
- Codex：Windows/Linux 支持 `TOKENPLAN_CODEX_HOMES` 和 Codex Swap 注册目录。macOS 还支持更多独立目录、pi 及钥匙串来源，不能视为所有平台完全一致。
- 其他服务：目前读取当前登录或已配置的 API Key，没有通用的多账号自动发现。
- 附加账号的逐条 token/费用日志归属尚未与 macOS 对齐；本地额度快照历史不等于完整消费账单。

本轮验证：420 项 Core 检查及 120 项界面检查通过；独立账号凭据、重复身份、token 更新后稳定标识、缺少凭据不回退均有回归覆盖。Windows/Linux 原生安装、托盘交互及实际账号刷新仍需对应系统实测。

### 菜单栏／托盘账号一致性修复

Windows/Linux 设置中的托盘服务列表现在每个账号只有一个开关，Claude 账号用 `Claude-邮箱` 标注；列表与托盘用量摘要共用服务顺序，相同服务的账号保持相邻。旧版关闭服务总开关的偏好仍受尊重，重新打开某个账号不会打开其余账号。托盘开关独立于首页账号可见性。

数字用量摘要优先采用勾选指标；没有勾选或勾选指标不可用时，使用主要额度（Claude 会话、Codex Pro 每周等），没有任何用量时不制造读数。原有勾选不变。Windows/Linux 使用原生托盘菜单摘要，尚未提供 macOS 的多圆环状态栏图标。

此轮 424 项功能检查及 125 项界面检查通过，覆盖独立开关数量、账号相邻排序、未勾选回退、旧总开关兼容；对应系统原生交互仍需安装实测。
